# Protocol buffer (`protobuf`) generation documentation

This document records which `.proto` sources are canonical, how the Python and Go bindings are generated, and where duplication/drift exists. It corresponds to PR #4 of the repository structure improvement plan. It is intentionally descriptive only — no files are moved or deleted here.

## Canonical `.proto` sources

### Python bindings (`gptc.proto` package)

There is no single canonical `.proto` file. Gptc maintains **two** versioned source trees because the protobuf wire format changed at protobuf 3.19 and because DocArray v1 and DocArray >=0.30 have incompatible proto definitions:

| Tree | Protobuf/DocArray | Generated output dir | Canonical sources |
|---|---|---|---|
| `gptc/proto/docarray_v1/` | protobuf < 3.19 / DocArray v1 | `pb2/` | `docarray_v1/gptc.proto`, `docarray_v1/docarray.proto` |
| `gptc/proto/docarray_v2/` | protobuf >= 3.19 / DocArray >=0.30 | `pb/` | `docarray_v2/gptc.proto`, `docarray_v2/docarray.proto` |

The `.proto` sources under `gptc/proto/docarray_v*/` are **identical** to those under `docs/proto/docarray_v*/` (verified: `gptc.proto` and `docarray.proto` match byte-for-byte in v1 and v2).

The top-level `gptc/proto/gptc_pb2.py` and `gptc_pb2_grpc.py` are generated bindings whose source version is ambiguous (they are not regenerated by either `build-proto.sh`). Treat them as legacy output until a single canonical location is chosen.

### Go bindings (`jraft` module, consensus)

Separate `.proto` sources live under `gptc/serve/consensus/`:
- `gptc/serve/consensus/gptc.proto`
- `gptc/serve/consensus/docarray.proto`

These are **not** the same files as the Python `.proto` sources above (different `go_package` options, different message set). They are compiled by `scripts/protogen.sh` into `gptc-go-proto/` and `docarray-go-proto/` for the native `jraft` extension. See NATIVE.md.

### Documentation copy (`docs/proto/`)

`docs/proto/` mirrors `gptc/proto/` (same `docarray_v1/`/`docarray_v2/` structure, same top-level generated files, plus `docs.md` and `index.md`). Its `.proto` **sources** match `gptc/proto/`, but its generated `.py` bindings **differ** from `gptc/proto/` (different protoc versions or manual edits). `docs/proto/` should be a **documentation-only copy**, kept synchronized with `gptc/proto/` sources — not an independent source of truth.

## Generation tooling (pinned via Docker)

Two Docker images pin the compiler/plugin versions:

| Dockerfile | Image | protoc | grpc plugin | Generates |
|---|---|---|---|---|
| `docker/protogen.Dockerfile` | `gptcomputer/protogen` | 3.19.1 | grpc v1.46.0 | `docarray_v1/` → `pb2/` |
| `docker/protogen-3.21.Dockerfile` | `gptcomputer/protogen-3.21` | 21.5 | grpc v1.48.0 | `docarray_v2/` → `pb/` |

Both images:
- Build from `python:3.10-slim-bookworm`
- Compile `grpc_python_plugin` from source (grpc repo, cmake build)
- Copy `gptc/proto/docarray_v*` into `/gptc/proto` and run `build-proto.sh`

Generation commands (from `gptc/proto/README.md`):

```bash
# DocArray v1 (protobuf < 3.19)
docker build -f docker/protogen.Dockerfile -t gptcomputer/protogen:local .
docker run -it -v $(pwd)/gptc/proto/docarray_v1:/gptc/proto gptcomputer/protogen:local
docker run -it -v $(pwd)/gptc/proto/docarray_v1:/gptc/proto gptcomputer/protogen-3.21:local

# DocArray >=0.30 (protobuf >= 3.19)
docker run -it -v $(pwd)/gptc/proto/docarray_v2:/gptc/proto gptcomputer/protogen:local
docker run -it -v $(pwd)/gptc/proto/docarray_v2:/gptc/proto gptcomputer/protogen-3.21:local
```

`build-proto.sh` runs `protoc --python_out --grpc_python_out` with a locally built `grpc_python_plugin`, then post-processes imports and bumps `__proto_version__` in `../__init__.py`.

## Known drift and breakage

1. **`docs/proto/` generated bindings diverge from `gptc/proto/`.** `diff -rq` shows every generated `.py` differs (`gptc_pb2.py`, `gptc_pb2_grpc.py` in `pb/` and `pb2/` for both versions, plus top-level files). The docs tree is not synchronized with the runtime tree.

2. **`__proto_version__` bump target is empty.** `build-proto.sh` reads/writes `__proto_version__` in `../__init__.py` (i.e. `gptc/proto/docarray_v*/__init__.py`), but those `__init__.py` files are empty — the version bump is a no-op and the read fails silently.

3. **Top-level `gptc/proto/gptc_pb2.py` / `gptc_pb2_grpc.py` are orphaned.** No build script regenerates them; it is unclear which proto version (v1 or v2) they correspond to, or whether they are still imported at runtime.

4. **No CI regeneration check.** There is no job that regenerates bindings and fails when checked-in output differs, so silent drift between `.proto` sources and generated bindings is possible.

5. **Python and Go `.proto` sources are separate.** The consensus `gptc.proto`/`docarray.proto` (Go) and `gptc/proto/docarray_v*/` (Python) evolve independently; a change to one is not reflected in the other.

## Rules

1. Treat `gptc/proto/docarray_v1/` and `gptc/proto/docarray_v2/` as the canonical Python `.proto` sources. Every other copy (`docs/proto/`) is documentation-only output.
2. Pin protoc/plugin versions via the `docker/protogen*.Dockerfile` images; do not regenerate with locally installed `protoc` of arbitrary version.
3. Keep `docs/proto/` sources synchronized with `gptc/proto/` sources; generated docs bindings may be regenerated for publishing but must not drift.
4. Add CI that regenerates `gptc/proto/docarray_v*` bindings with the pinned images and fails on uncommitted diff (see PR #4 completion check).
5. Resolve the orphaned top-level `gptc/proto/gptc_pb2.py` / `gptc_pb2_grpc.py` — either assign them to a canonical version or remove them once runtime import usage is confirmed.
6. Fix the `__proto_version__` target (`docarray_v*/__init__.py`) or remove the version-bump logic from `build-proto.sh`.

## Completion checks (PR #4)

- CI regenerates `docarray_v1` and `docarray_v2` bindings with the pinned protogen images and fails when `git diff --stat` is non-empty.
- `docs/proto/` `.proto` sources match `gptc/proto/` `.proto` sources (automated diff test).
- `import gptc.proto` and `import gptc.proto.docarray_v{1,2}` work from an installed wheel; required `pb`/`pb2` bindings are present.
- `gptc/serve/consensus/` Go `.proto` sources and `gptc/proto/docarray_v*/` Python `.proto` sources are listed side by side with their owners.
